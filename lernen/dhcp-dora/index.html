DHCP-DORA lesen und sicher erklären

Prüfungsrelevanz: hoch ≈ 18 Min. noch offen Pilot · fachlich in Prüfung

DORA ist keine bloße Buchstabenfolge. Die vier Nachrichten lösen nacheinander vier Probleme: Server finden, Konfiguration anbieten, ein Angebot auswählen und die Lease bestätigen. Wer zusätzlich den Zustand des Clients betrachtet, kann auch Paketziele im Mitschnitt sinnvoll erklären.

Nach dieser Einheit kannst du …

  • die vier DORA-Nachrichten ordnen und den Zweck jeder Nachricht aus Client- und Serversicht erklären
  • Broadcast- und Unicast-Verhalten eines DHCP-Mitschnitts ohne unzulässige Verallgemeinerung begründen

1Einstieg: Wer entscheidet wann?

Welche DHCP-Nachricht zeigt im initialen Ablauf, welches Angebot der Client anfordert?

DORA als Dialog

Client entdeckt, Server bietet, Client fordert, Server bestätigt. Damit bleiben Richtung und Zweck zusammen im Gedächtnis.

2Die vier Nachrichten verstehen

Discover: Der noch unkonfigurierte Client sucht einen DHCP-Server. Offer: Ein Server bietet eine noch zu bestätigende Konfiguration an. Request: Der Client fordert ein ausgewähltes Angebot an. Acknowledge: Der ausgewählte Server bestätigt Lease und Optionen; erst jetzt übernimmt der Client die Konfiguration regulär.

Mehrere Server dürfen auf ein Discover antworten. Deshalb ist Offer noch keine endgültige Zuweisung. Der initiale Request ist außerdem nicht mit einem späteren Renewal-Request gleichzusetzen: Beim Renewal kennt der Client seine Adresse und den bisherigen Server bereits.

3Geführte Übung: Ablauf rekonstruieren

Vier Nachrichten richtig ordnen

Ein neuer Client startet ohne Lease. Bringe Nachrichten und Zweck in die richtige zeitliche Reihenfolge.

Pflichtnachweis
  1. 1Discover: Der Client sucht erreichbare DHCP-Server.
  2. 2Offer: Ein Server schlägt Konfiguration und Lease vor.
  3. 3Request: Der Client fordert das ausgewählte Angebot an.
  4. 4Acknowledge: Der Server bestätigt die Zuweisung.

Im Mitschnitt folgen auf Discover zwei Offers. Danach erscheint ein Request des Clients. Warum ist das plausibel?

4Broadcast und Unicast im Mitschnitt

Ein initiales Discover wird typischerweise als lokaler Broadcast gesendet: Der Client kennt noch keinen DHCP-Server und hat häufig noch keine nutzbare Adresse. Der initiale Request wird typischerweise ebenfalls breit sichtbar gesendet, damit anbietende Server die Auswahl erkennen können.

Für Offer und Acknowledge ist die Aussage nicht so starr. Ob eine Antwort als Broadcast oder Unicast erscheint, hängt vom Zustand und den Fähigkeiten des Clients, gesetzten Flags, einem möglichen Relay und der konkreten Implementierung ab. Ein einzelner Mitschnitt, in dem alle vier Nachrichten an 255.255.255.255 gehen, beweist deshalb nicht, dass dies immer so sein muss.

DORA nicht mit Renewal vermischen

Nach T1 versucht ein Client die bestehende Lease zunächst mit einem Request direkt an den bisherigen Server zu verlängern. Das ist kein neuer vollständiger Discover–Offer–Request–Acknowledge-Durchlauf.

5Beispiel: Mitschnitt fachlich kommentieren

Ein Capture zeigt Discover, Offer, Request und ACK jeweils mit dem Ziel 255.255.255.255. Eine gute Auswertung lautet: Der Client startete ohne bestätigte Konfiguration; der beobachtete Ablauf verwendete Broadcastzustellung. Discover suchte Server, Offer schlug eine Konfiguration vor, Request wählte sie aus und ACK bestätigte die Lease.

Eine zu starke Auswertung wäre: „ACK ist bei DHCP immer Broadcast.“ Das Capture belegt nur diesen Ablauf. Für eine belastbare Diagnose prüfst du zusätzlich Broadcast-Flag, Clientzustand, Relaypfad und Serverkonfiguration.

Ein Wireshark-Capture zeigt ein DHCP-Acknowledge als Broadcast. Welche Schlussfolgerung ist fachlich am stärksten?

0 Zeichen notiert
Muster: Der Client sucht per Discover nach Servern. Ein Server bietet per Offer eine Konfiguration an. Der Client fordert mit Request das ausgewählte Angebot an, der Server bestätigt es mit Acknowledge. Discover und initialer Request sind typischerweise Broadcast. Offer und ACK können je nach Zustand, Flags, Relay und Implementierung als Broadcast oder Unicast zugestellt werden; ein Capture zeigt nur den konkreten Fall.
