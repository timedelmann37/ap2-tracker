Ein fremdes Skript Zeile für Zeile verfolgen, eine falsche Zählung erklären und eine gezielte Korrektur mit Grenzfällen absichern. Du bearbeitest eigene Papierfälle; es werden keine echten Systeme verändert.

Nach dieser Einheit kannst du …

  • Die tatsächliche Ausgabe aus den Zustandsänderungen ableiten
  • Einen logischen Fehler korrigieren und mit Gegenproben prüfen

1Vorwissen aktivieren

Ein Skript läuft ohne Fehlermeldung. Ist das Ergebnis damit fachlich richtig?

2Vier Fragen vor jeder Änderung

Lies ein fremdes Skript in vier Schritten: Welche Eingaben gibt es? Welche Werte ändern sich? Wann entsteht eine Ausgabe? Was wäre laut Auftrag richtig?

Unser Auftrag: Zähle alle Einträge mit Status Stopped. Für jeden Treffer soll die laufende Trefferzahl erscheinen; am Schluss die Gesamtzahl. Eingaben sind vorgegebene Textwerte, keine Abfragen echter Dienste. Der Code ist absichtlich fehlerhaft. Kommentiere zuerst seinen tatsächlichen Ablauf, bevor du ihn verbesserst.

3Erst vorhersagen, dann verfolgen

Notiere alle Ausgabezeilen in der richtigen Reihenfolge. Achte besonders darauf, welche Zeilen innerhalb der Schleife stehen.

$statusListe = @(
  'Stopped', 'Running', 'Stopped'
)
$anzahl = 0
foreach ($status in $statusListe) {
  $anzahl = 0
  if ($status -eq 'Stopped') {
    $anzahl = $anzahl + 1
    "Treffer: $anzahl"
  }
}
"Gesamt: $anzahl"

Die Initialisierung vor der Schleife setzt den Anfangszustand. Die zweite Zuweisung innerhalb der Schleife überschreibt dagegen jedes Mal den bisherigen Zähler. $status -eq 'Stopped' prüft den aktuellen einzelnen Textwert.

Durchlauf Status Nach Zurücksetzen Nach Bedingung Ausgabe
1 Stopped 0 1 Treffer: 1
2 Running 0 0 keine
3 Stopped 0 1 Treffer: 1

Danach folgt Gesamt: 1. Die vollständige Ausgabe lautet also:

Treffer: 1
Treffer: 1
Gesamt: 1

Der Auftrag verlangt zwei Treffer insgesamt. Das Programm liefert aber den Zustand nach dem letzten Durchlauf. Bei einem letzten Running wäre die Gesamtzahl sogar null. Der Fehler ist logisch, nicht syntaktisch.

Im unveränderten fehlerhaften Skript stehen jetzt Stopped, Stopped, Running. Welcher Zahlenwert erscheint hinter Gesamt?

4Die kleinste sinnvolle Korrektur

Welche einzelne Änderung behebt die verlorene Gesamtzählung?

Die Korrektur lässt die einmalige Initialisierung stehen. Der Zähler wächst nur bei einem Treffer und behält sonst seinen Wert.

$statusListe = @(
  'Stopped', 'Running', 'Stopped'
)
$anzahl = 0
foreach ($status in $statusListe) {
  if ($status -eq 'Stopped') {
    $anzahl = $anzahl + 1
    "Treffer: $anzahl"
  }
}
"Gesamt: $anzahl"

Für die ursprüngliche Liste entsteht Treffer: 1, dann Treffer: 2, dann Gesamt: 2. Die Folge der Zählerwerte nach den drei Durchläufen ist 1, 1, 2. Die fachliche Invariante lautet: Nach jedem Durchlauf entspricht der Zähler der Zahl der bisher gesehenen Stopped-Einträge. Diese Aussage hilft dir auch bei anderen Zählaufgaben.

5Nicht nur den einen Beispieldatensatz testen

Leite Tests aus dem Fehler ab. Ein einziger gestoppter Eintrag hätte den Fehler verdeckt: Auch die fehlerhafte Version meldet dafür eins. Mehrere Treffer und ein letzter Nichttreffer machen ihn sichtbar.

Eingabe Soll nach Korrektur Warum wichtig?
Stopped, Stopped Gesamt: 2 Frühere Treffer müssen erhalten bleiben
Stopped, Running Gesamt: 1 Nichttreffer darf Zähler nicht löschen
Running Gesamt: 0 Kein Treffer
leere Liste Gesamt: 0 Schleife läuft keinmal

Bei leerer Liste ist die Initialisierung vor der Schleife weiterhin nötig. Entferne also nicht beide Zuweisungen. Ein Testprotokoll hält Eingabe, erwartete Ausgabe, beobachtete Ausgabe und Ergebnis getrennt fest.

6Gezielt ergänzen statt alles umschreiben

Neuer Auftrag: Zusätzlich Running zählen und alle übrigen gelieferten Statuswerte als andere ausweisen. Ein Zustand wie Paused ist nicht dasselbe wie Stopped. Der folgende Pseudocode beschreibt nur die Datenverarbeitung:

gestoppt := 0
laufend := 0
andere := 0
FÜR JEDEN status IN statusListe
  WENN status = "Stopped"
    erhöhe gestoppt um 1
  SONST WENN status = "Running"
    erhöhe laufend um 1
  SONST
    erhöhe andere um 1
GIB gestoppt, laufend, andere AUS

Für Running, Paused, Stopped, Running erhältst du laufend 2, gestoppt 1 und andere 1. Jeder Datensatz landet in genau einem Zweig. Ein Fehler beim Abrufen wäre dagegen ein eigener Fehlerfall außerhalb dieser Liste; er darf nicht als tatsächlich gelieferter Dienststatus erfunden werden.
