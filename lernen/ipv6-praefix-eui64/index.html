IPv6-/64-Präfixe und Modified EUI-64 einordnen

Prüfungsrelevanz: hoch ≈ 24 Min. noch offen Pilot · fachlich in Prüfung

Ein übliches IPv6-LAN mit SLAAC verwendet ein /64-Präfix: Die oberen 64 Bit bezeichnen das Subnetz, die unteren 64 Bit die Interface-ID. Modified EUI-64 ist eine mögliche und prüfungsrelevante Bildung dieser ID, aber heute nicht die pauschal empfohlene Standardwahl für Clientadressen.

Nach dieser Einheit kannst du …

  • aus einem delegierten IPv6-Präfix die Anzahl verfügbarer /64-LAN-Präfixe berechnen und ein gültiges /64 bilden
  • eine Modified-EUI-64-Interface-ID aus einer MAC-Adresse ableiten und gegenüber modernen stabilen oder temporären Interface-IDs einordnen

1Einstieg: Was bleibt bei /64 übrig?

Welche Aufteilung beschreibt eine gewöhnliche IPv6-LAN-Adresse mit /64?

/64 richtig einordnen

Für ein gewöhnliches SLAAC-LAN gilt 64 Bit Präfix plus 64 Bit Interface-ID. Ein größeres delegiertes Präfix liefert die Bits für mehrere solcher LANs.

2Ein /56 in /64-LANs aufteilen

Das Unternehmen erhält 2001:db8:44aa:1200::/56. Die ersten 56 Bit stehen fest. Bis zur gewünschten LAN-Grenze /64 bleiben acht Bit für die Subnetz-ID. Dadurch entstehen 256 verschiedene /64-Präfixe.

Das vierte Hextet reicht im delegierten Bereich von 1200 bis 12ff. Die Wahl der Subnetz-ID 2a erzeugt das LAN-Präfix 2001:db8:44aa:122a::/64. Diese Adresse ist die Präfixdarstellung; eine vollständige Hostadresse benötigt zusätzlich eine 64-Bit-Interface-ID.

264−56=28=256 mögliche /64-LANs
56 bereits festgelegte Präfixbits64 gewünschte LAN-Präfixbitsacht freie Bit für die Subnetz-ID

3Durchgearbeitetes Modified-EUI-64-Beispiel

Für eine Laboraufgabe soll aus der MAC-Adresse 00:1a:2b:3c:4d:5e ausdrücklich eine Modified-EUI-64-ID gebildet werden. Die MAC wird nach dem dritten Byte geteilt. Dazwischen wird ff:fe eingefügt. Danach wird im ersten Oktett das U/L-Bit invertiert; rechnerisch wird 00 mit 02 exklusiv ODER verknüpft.

Es entsteht die Interface-ID 021a:2bff:fe3c:4d5e. Mit dem zuvor gebildeten Präfix lautet die gekürzte Adresse 2001:db8:44aa:122a:21a:2bff:fe3c:4d5e. Die führende Null im ersten IID-Hextet entfällt nur in der Schreibweise, nicht im 64-Bit-Wert.

00hex⊕02hex=02hex
⊕ = exklusives ODER02 hex markiert das zu invertierende U/L-Bit im ersten Oktett
Privacy Extensions nicht vergessen

Eine MAC-abgeleitete IID ist über Netze und Zeit leichter wiederzuerkennen. Moderne Systeme verwenden häufig stabile semantisch opake IIDs und für ausgehende Clientverbindungen zusätzlich temporäre Privacy-Adressen. Aus einer beobachteten IPv6-Adresse darf deshalb nicht pauschal eine MAC rekonstruiert werden.

4Geführte Übung: EUI-64 nur auf ausdrückliche Anforderung

Modified-EUI-64-Schritte

Bringe die Schritte für die MAC 0c:4d:e9:12:34:56 in die richtige Reihenfolge.

Übung
  1. 1U/L-Bit im ersten Oktett invertieren.
  2. 248-Bit-MAC in zwei 24-Bit-Hälften teilen.
  3. 3Das 64-Bit-Ergebnis als vier Hextets gruppieren.
  4. 4Zwischen den Hälften ff:fe einsetzen.

Ohne Nachschlagen erklären

Erkläre die Aufteilung eines /56 in /64-LANs und bilde anschließend verbal eine Modified-EUI-64-IID. Ordne das Verfahren gegenüber Privacy Extensions ein.

0 Zeichen notiert
Muster: Zwischen /56 und /64 liegen acht Subnetzbits, also 256 mögliche /64-LANs. Für Modified EUI-64 wird eine 48-Bit-MAC geteilt, ff:fe eingesetzt und das U/L-Bit des ersten Oktetts invertiert. Das Ergebnis bildet eine 64-Bit-IID. Moderne Clients verwenden häufig stabile opake und zusätzliche temporäre IIDs, damit die Adresse nicht dauerhaft die Hardwarekennung offenlegt.
