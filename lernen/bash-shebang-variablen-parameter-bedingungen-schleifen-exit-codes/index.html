Bash: Argumente, Ausgabe und Exit-Status lesen

Prüfungsrelevanz: hoch ≈ 25 Min. noch offen Pilot · fachlich in Prüfung

Argumentgrenzen erhalten, eine Schleife nachvollziehen und Standardausgabe von Fehlerausgabe und Exit-Status unterscheiden. Du bearbeitest eigene Papierfälle; es werden keine echten Systeme verändert.

Nach dieser Einheit kannst du …

  • Argumente und Leerwerte in einer Bash-Schleife richtig verfolgen
  • Datenströme und Pipeline-Status unterscheiden

1Vorwissen aktivieren

Ein Skript wird mit "Nord West" als einem Argument aufgerufen. Was bewahrt dieses Argument in der for-Schleife?

2Aufruf und Variablen

Die Shebang-Zeile #!/usr/bin/env bash wählt beim direkten ausführbaren Skriptaufruf Bash über die Suchpfade aus. Bei bash namen.sh ... wird Bash ausdrücklich gestartet. Die folgenden Beispiele setzen Bash voraus, nicht beliebiges sh.

Eine Zuweisung lautet anzahl=0, ohne Leerzeichen um das Gleichheitszeichen. $1 bezeichnet das erste Skriptargument, $# die Argumentanzahl. "$@" erhält die einzelnen Argumente, einschließlich übergebener Leerwerte. $0 ist beim gewöhnlichen Skriptaufruf der Skriptname, nicht stdin.

3Erst vorhersagen, dann verfolgen

Das Skript gibt nichtleere Namen aus und zählt sie. Es löscht, liest und ändert keine Dateien. Wenn keine Argumente übergeben werden, meldet es einen Eingabefehler. Ein ausdrücklich übergebener leerer Text ist dagegen ein Argument, wird aber nicht gezählt.

#!/usr/bin/env bash
if [ "$#" -eq 0 ]; then
  printf '%s\n' 'Keine Namen' >&2
  exit 2
fi
anzahl=0
for name in "$@"; do
  if [ -n "$name" ]; then
    printf '%s\n' "$name"
    anzahl=$((anzahl + 1))
  fi
done
printf 'Anzahl: %s\n' "$anzahl"
exit 0

[ "$#" -eq 0 ] vergleicht Zahlen. [ -n "$name" ] prüft, ob der Text nicht leer ist. Die Leerzeichen an den eckigen Klammern sind erforderlich. then/fi begrenzen den if-Zweig, do/done den Schleifenrumpf.

Sage die Ausgabe für bash namen.sh "Nord West" "" Sued voraus. Drei Argumente kommen an. Die Schleife zählt den ersten und dritten Eintrag; der leere zweite Eintrag wird übersprungen.

Nord West
Sued
Anzahl: 2

Der Exit-Status ist null. Ohne Argumente gibt es keine Standardausgabe, nur Keine Namen auf stderr und Status zwei. Bei genau einem leeren Argument gibt es Anzahl: 0 auf stdout und Status null. Diese Unterscheidung ist Teil unseres ausdrücklich gewählten Vertrags.

4Datenstrom ist nicht Parameter

Die Dateideskriptoren 0 = stdin, 1 = stdout, 2 = stderr sind nicht die Positionsparameter $0, $1, $2. >&2 schreibt die Ausgabe unseres printf auf stderr.

programm | filter verbindet gewöhnlich stdout des linken Programms mit stdin des rechten; stderr wird nicht automatisch mitgeleitet. < datei liest aus einer Datei, > datei schreibt stdout und kann vorhandenen Inhalt abschneiden. >> datei hängt an; 2> datei leitet stderr um. Diese Schreibweisen werden hier nur gelesen, nicht auf Dateien ausgeführt.

$? liefert den Status des zuletzt abgeschlossenen Vordergrundbefehls beziehungsweise der Pipeline. Sichere ihn sofort, wenn ein weiterer Befehl folgen soll. Null bedeutet für die Shell Erfolg; andere Werte kennzeichnen einen nicht erfolgreichen Status, dessen genaue Bedeutung zum Befehl gehört.

5Den versteckten Pipelinefehler finden

Eigener Prüfungsfall: false | true. Ohne pipefail gilt der Status des letzten Befehls: null. Mit set -o pipefail ergibt dieselbe Pipeline eins. pipefail lässt den rechten nicht erfolgreichen Status der Pipeline gelten; es prüft nicht die fachliche Richtigkeit von Ausgabedaten. Diese Aussage betrifft Bash, nicht automatisch andere Shells.

Ohne pipefail liefert der linke Befehl Fehlerstatus 1, der letzte Status 0. Welchen Pipeline-Status erhältst du?
