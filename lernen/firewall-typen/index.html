Firewalltypen nach ihrer Prüftiefe auswählen

Prüfungsrelevanz: hoch ≈ 25 Min. noch offen Pilot · fachlich in Prüfung

Eine erlaubte TCP-Verbindung kann schädliche Anwendungsdaten transportieren. Ob eine Firewall das erkennt, hängt davon ab, welche Merkmale sie tatsächlich prüft. Der Produktname allein beantwortet diese Frage nicht.

Nach dieser Einheit kannst du …

  • Paketmerkmale, Verbindungszustand und Anwendungsinhalt dem passenden Firewallverfahren zuordnen
  • eine Firewallentscheidung für verschlüsselten Verkehr mit Sichtbarkeits- und Betriebsgrenzen begründen

1Vorwissen aktivieren

Eine Firewall erlaubt TCP/443. Welche Aussage folgt daraus?

Leitgedanke

Frage zuerst: Welche Information muss die Entscheidung tragen – Paketkopf, Verbindung oder Anwendung?

2Vier Verfahren, unterschiedliche Aussagen

Ein stateless Paketfilter prüft jedes Paket anhand von Merkmalen wie Quell-/Zieladresse, Protokoll und TCP-/UDP-Port. Er kennt dadurch noch keinen vollständigen Gesprächsverlauf.

Stateful Inspection führt einen Zustandsspeicher. Rückverkehr kann einer zuvor erlaubten Kommunikation zugeordnet werden; für UDP verwendet das System zeitbegrenzten Pseudozustand. Ein gesetztes ACK-Bit ist allein kein solcher Nachweis.

Ein Application Gateway/Proxy vermittelt eine Anwendung und kann deren Protokoll verstehen. Es beendet und eröffnet Verbindungen in seiner Stellvertreterrolle. Eine NGFW bündelt häufig Stateful Filtering, Anwendungserkennung und IDS/IPS. Welche Funktion aktiv ist, muss geprüft werden.

Bei TLS sind Nutzdaten verschlüsselt. Ohne geeignete Terminierung oder Inspektion bleiben Inhalte verborgen; Metadaten können weiterhin sichtbar sein. Eine Entschlüsselung schafft zusätzliche Anforderungen an Vertrauen, Schlüssel und Betrieb.

3Durchgearbeitetes Beispiel

Ein Unternehmen will zuerst nur ausgehendes HTTPS erlauben und dazugehörige Antworten zurücklassen. Eine Stateful Firewall kann diese Transportanforderung erfüllen. Zweitens soll ein bestimmter HTTP-Upload untersagt werden. Das verlangt Anwendungssicht: Bei verschlüsseltem HTTPS reicht die erste Regel nicht. Ein kontrollierter Anwendungsproxy oder eine passende Prüfung am Server muss Inhalt und Regel zusammenbringen. Auch diese Kontrolle beweist nicht, dass jeder verbleibende Upload harmlos ist.

Eine unbekannte eingehende Verbindung trägt ACK. Reicht das für die Freigabe durch Stateful Inspection?

Deine Begründung

Begründe für HTTPS-Rückverkehr und Uploadfilter zwei unterschiedliche Prüfanforderungen. Nenne jeweils eine Grenze.

0 Zeichen notiert
Muster: Stateful Filtering ordnet Rückverkehr einer erlaubten Kommunikation zu. Ein Uploadfilter benötigt Sicht auf die Anwendung, bei HTTPS also eine passende Terminierung oder Inspektion. Beide Kontrollen brauchen konkrete Regeln und negative Tests; keine garantiert Schadsoftwarefreiheit.
