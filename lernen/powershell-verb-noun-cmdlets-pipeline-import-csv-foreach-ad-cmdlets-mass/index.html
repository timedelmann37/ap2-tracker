Eine Objektpipeline lesen, CSV-Datensätze filtern und die Vorbereitung einer Benutzeranlage von ihrer Ausführung trennen. Du bearbeitest eigene Papierfälle; es werden keine echten Systeme verändert.

Nach dieser Einheit kannst du …

  • CSV-Objekte filtern und foreach-Ausgaben nachvollziehen
  • Eine kontrollierte Benutzeranlage aus CSV vorbereiten

2Cmdlets und Objektpipeline

Cmdlet-Namen folgen dem Muster Verb-Noun: Get-Command ermittelt Befehle, Import-Csv importiert CSV-Daten. Das Verb beschreibt die Handlung, das Nomen den Gegenstand. Get-Help hilft, Parameter und Eingabeformen zu prüfen.

Zwischen PowerShell-Cmdlets werden normalerweise Objekte weitergereicht. Diese besitzen Eigenschaften, beispielsweise Name und Abteilung. In Where-Object { $_.Abteilung -eq 'IT' } steht $_ für das gerade verarbeitete Objekt. Der Filter lässt passende Objekte passieren. Das ist nicht dasselbe wie das Durchsuchen einer bereits formatierten Bildschirmzeile. Native Programme können sich anders verhalten; unsere Einheit bleibt bei PowerShell-Objekten.

3CSV zuerst richtig lesen

Für eine bereitgestellte Datei würde der Import so aussehen:

$daten = Import-Csv `
  -LiteralPath '.\team.csv' `
  -Delimiter ';'

Der Inhalt bestimmt das Trennzeichen, nicht die Dateiendung. Hier heißt die Kopfzeile Name;Abteilung. Mit dem falschen Trennzeichen entstehen nicht die erwarteten Eigenschaften. Prüfe Überschriften und Beispielwerte vor der Weiterverarbeitung. Gewöhnliche importierte Feldwerte sind zunächst Text: Eine Ziffernfolge ist nicht automatisch ein sinnvoll validierter Zahlenwert.

Damit unser ausführbares Beispiel keine Datei benötigt, nutzt es ConvertFrom-Csv auf eingebettetem Text. Das stellt dieselben Übungsdaten ohne Dateizugriff bereit. Sage zuerst voraus, welche Namen und welche Anzahl erscheinen.

$csv = @'
Name;Abteilung
Ada;IT
Ben;Vertrieb
Cem;IT
'@
$daten = $csv |
  ConvertFrom-Csv -Delimiter ';'
$auswahl = @(
  $daten | Where-Object {
    $_.Abteilung -eq 'IT'
  }
)
foreach ($person in $auswahl) {
  $person.Name
}
"Anzahl: $($auswahl.Count)"

@(...) sammelt die Auswahl als Array, auch bei keinem oder nur einem Treffer. Die foreach-Anweisung weist $person nacheinander jedem ausgewählten Objekt zu. Sie ist ein Sprachkonstrukt; ForEach-Object ist dagegen ein Cmdlet für die Pipeline. In dieser Einheit nutzen wir die ausgeschriebene foreach-Anweisung.

Ada und Cem gehören zu IT, Ben nicht. Die Ausgabe lautet:

Ada
Cem
Anzahl: 2

Kein Treffer ergibt ein leeres Array: Der Schleifenrumpf läuft nicht, die Anzahl ist null. Bei genau einem IT-Datensatz läuft er einmal. So bleiben Leer- und Einzelfall ausdrücklich definiert.

4Typische Fehler erkennen

Die Datei nutzt Semikola, Import-Csv aber ein Komma als Trennzeichen. Warum kann der Abteilungsfilter scheitern?

Ein Filterfehler ist kein Anlass, sofort Konten anzulegen. Kontrolliere die Daten mit Eigenschaften statt formatiertem Text. Halte Einlesen, Validieren und Ändern getrennt. Der bloße Import validiert weder einen zulässigen Login noch eine existierende Ziel-OU.

5Benutzeranlage nur nach Prüfung

New-ADUser aus dem ActiveDirectory-Modul erstellt ein Benutzerobjekt. Für einen echten Lauf braucht es eine passende Verwaltungsumgebung, erreichbares Verzeichnis und Berechtigungen. -Name, -SamAccountName und -Path bestimmen wichtige Zielwerte; ein Konto anzulegen ist nicht dasselbe wie es sicher zur Anmeldung zu aktivieren.

Eigener Ablauf: Die CSV enthält die Spalten Name und Login. Prüfe vor dem ersten Schreibzugriff leere Pflichtfelder, doppelte Logins innerhalb der Datei, bereits vorhandene Konten und die freigegebene Test-OU. Eingaben nicht blind als Befehle ausführen. Der folgende Ausschnitt ist nur ein Lese- und Zuordnungsbeispiel: $geprueft und $testOu müssen zuvor kontrolliert feststehen.

foreach ($person in $geprueft) {
  New-ADUser -Name $person.Name `
    -SamAccountName $person.Login `
    -Path $testOu `
    -Enabled $false -WhatIf
}

-WhatIf zeigt bei diesem Cmdlet die beabsichtigte Aktion, ohne sie auszuführen. Das beweist nicht, dass eine spätere echte Anlage sämtliche Anforderungen erfüllt. Keine automatische Passwortvergabe, keine Aktivierung und keine Produktionsfreigabe sind Bestandteil des Beispiels. Zugangsdaten gehören nicht in CSV-Dateien oder Logs. Nach einem freigegebenen echten Lauf wären Ergebnisprüfung und ein nachvollziehbares Fehlerprotokoll erforderlich.

Ordne die Vorbereitung einer Benutzeranlage.
