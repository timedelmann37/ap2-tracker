1Vorwissen aktivieren

Ein Ping auf 127.0.0.1 gelingt. Ist das Netzwerkkabel geprüft?

Leitgedanke

Ein Kommando ist nur so hilfreich wie die Frage davor. Du wählst gezielte Tests und vermeidest den Fehlschluss: Ping geht, also funktioniert alles.

2Konfiguration, Pfad und Dienst getrennt prüfen

ipconfig /all zeigt unter Windows unter anderem Adressen, DNS-Server und DHCP-Informationen. Unter Linux zeigt ip a Interface-Adressen, ip route die IPv4-Routen; ip -6 route betrachtet IPv6. Eine Adresse allein beweist weder ein passendes Gateway noch Erreichbarkeit. arp -a zeigt den IPv4-Nachbarcache, ip neigh auch Nachbarzustände; IPv6 verwendet Neighbor Discovery statt ARP.

ping prüft ICMP-Echo und misst die Round-Trip-Zeit seiner Pakete. ping 127.0.0.1 prüft den lokalen IP-Stack, nicht Kabel oder Switch. tracert unter Windows und traceroute unter Linux erkunden mit begrenzter TTL beziehungsweise Hop Limit den Weg. Probearten und Optionen unterscheiden sich. Ein Stern bedeutet fehlende Antwort auf eine Probe, nicht automatisch fehlende Weiterleitung.

nslookup portal.example 10.44.0.53 fragt gezielt einen DNS-Server. Mit dig @10.44.0.53 portal.example A lässt sich eine bestimmte Recordart prüfen. Das Ergebnis ist nicht zwangsläufig identisch mit dem Auflösungsweg einer Anwendung mit Cache, VPN oder eigenem Resolver.

ss -lnt zeigt unter Linux lauschende TCP-Sockets numerisch; netstat -ano zeigt unter Windows Verbindungen, Listener und Prozess-IDs. Ein Listener auf Loopback ist nicht automatisch aus dem Netz erreichbar. nc -vz -w 3 10.44.0.20 443 ist ein gezielter TCP-Verbindungstest in der OpenBSD-Variante; andere nc-Versionen unterscheiden sich. Erfolg beweist keinen TLS-Handshake und keine funktionierende Webanwendung. Nutze aktive Tests nur für freigegebene Ziele, nicht als unkontrollierten Netzscan.

3Durchgearbeitetes Beispiel

Im freigegebenen Labor öffnet portal.example nicht. ipconfig /all zeigt den vorgesehenen Resolver; nslookup portal.example 10.44.0.53 liefert 10.44.0.20. Ein TCP-Test zu Port 443 gelingt. Damit sind eine DNS-Antwort und ein TCP-Verbindungsaufbau aus diesem Testkontext belegt.

Der Browser meldet trotzdem einen Zertifikatsfehler. Statt Router und Kabel auszutauschen, prüfst du nun Hostname, Systemzeit, Zertifikatskette und den tatsächlich erreichten Dienst. Ein erfolgreicher TCP-Test bestätigt nicht diese höheren Ebenen.

Ein zweiter Fall: tracert zeigt bei Hop 3 einen Stern, aber das Ziel antwortet später. Hop 3 kann Probes filtern oder nachrangig behandeln, während Nutzdaten weitergeleitet werden. Dokumentiere den gesamten Pfad und Zielbefund; beschuldige nicht allein anhand eines Sterns diesen Router.
